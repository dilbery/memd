01

People & interactive agents

Configure your agent with the MCP server URL below, then use its {{ org_name() }} sign-in flow.

{{ origin }}

OIDC gives the agent access to your own memory store. An administrator token is not needed.

02

Services & automation

Create a token for one named store. Select only the operations the job needs, and record an owner and purpose.

Store the credential in the service's secret store and send it in the Authorization: Bearer <token> header.

Use the same credential for REST or MCP. Never put it in a URL.

03

Rotate without interruption

Rotate an active token to receive its replacement. The default overlap is 24 hours, bounded by the old token's existing expiry.

Update the consuming service, confirm it works, then revoke the old token.

04

Retire legacy access

Legacy credentials retain their existing access. Replace human use with a tested OIDC login and automation with explicitly scoped tokens.

Revocation takes effect on the next operation. A request already running may finish.
